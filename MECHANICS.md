# Полная механика платформы TransferMarket SPC

---

## 1. Роли и авторизация

### Роли пользователей
- **admin** — полный доступ ко всем функциям, административные панели, симуляция матчей, управление лигами/турнирами
- **coach** — тренер, привязан к одной команде; управляет своим клубом, составом, участвует в аукционах, делает трансферные предложения
- Неавторизованные пользователи — только просмотр публичных страниц

### Регистрация и профиль тренера
- При регистрации создаётся аккаунт `user`, затем тренер создаёт профиль `coach` и привязывается к команде
- Профиль тренера: имя, аватар, возраст, рост, стиль игры (4-4-2 и т.д.), описание
- Тренер может изменить название команды (ограничение: не более заданного числа изменений за сезон, `season_name_changes`)
- Загрузка аватара тренера через canvas-кроппер (соотношение 1:1)

## 2. Команды

### Данные команды
Каждая команда хранит: название, короткое название, страну, лигу, год основания, стадион, логотип, рыночную стоимость (сумма стоимостей игроков), трансферный бюджет, потраченный бюджет.

### Визуальные настройки (загружаются тренером через кроппер)
- **Логотип** (соотношение 1:1)
- **Фото «О клубе»** (16:9)
- **Баннер гола** — показывается при забитом мяче в матче (16:9)
- **Фото стадиона** (16:9)
- **Три комплекта формы**: домашняя, выездная, третья (16:9)
- Цвета команды: основной, дополнительный, паттерн (полосы/соты/т.д.)

### Трансферный бюджет
- Начальный баланс: **€10 000 000** при старте каждого нового сезона
- Бюджет пополняется при продаже игроков
- Тренер видит доступный бюджет: `transfer_budget − transfer_budget_spent`
- При старте лиги все команды получают расчётный сезонный бюджет (`season_budgets`) — формула: `max(3 000 000, market_value × 0.22)`, с поправками:
  - Команда слабее 70% медианы по рынку → ×1.4
  - Слабее 90% медианы → ×1.2
  - Сильнее 130% медианы → ×0.85

## 3. Игроки

### Основные атрибуты
- Имя, дата рождения, национальность, позиция, доп. позиция, нога, рост
- Рыночная стоимость (обновляется по результатам матчей)
- Статус: `active` / `free_agent` / `in_pack` / `retired`
- `ovr_fixed` — фиксированный OVR (назначается игрокам из паков)
- `free_agent_since` — дата появления в пуле свободных агентов

### Позиции (11 типов)
Goalkeeper, Centre-Back, Left-Back, Right-Back, Defensive Midfield, Central Midfield, Attacking Midfield, Left Winger, Right Winger, Centre-Forward, Striker

### Навыки игрока (player_skills)
5 параметров от 25 до 99: **Pace, Shooting, Passing, Defending, Physical**

Начальные навыки генерируются из рыночной стоимости:
```
base = clamp(52 + (log10(max(mv, 100_000)) - 5) × 13, 38..88)
```
Затем к базе прибавляются ролевые бонусы и случайность (±11).

### OVR (Overall Rating)
Вычисляется из навыков по позиции (точные коэффициенты из SQL):
| Позиция | Формула |
|---|---|
| Goalkeeper | defending×0.30 + passing×0.15 + physical×0.20 + pace×0.10 + shooting×0.05 + 20 |
| Centre-Back | defending×0.35 + physical×0.25 + passing×0.15 + pace×0.15 + shooting×0.10 |
| Left-Back / Right-Back | defending×0.30 + pace×0.25 + physical×0.20 + passing×0.15 + shooting×0.10 |
| Defensive Midfield | defending×0.30 + passing×0.25 + physical×0.20 + shooting×0.15 + pace×0.10 |
| Central Midfield | passing×0.30 + shooting×0.20 + pace×0.20 + defending×0.15 + physical×0.15 |
| Attacking Midfield | shooting×0.30 + passing×0.25 + pace×0.20 + defending×0.15 + physical×0.10 |
| Left / Right Winger | pace×0.30 + shooting×0.30 + passing×0.20 + physical×0.10 + defending×0.10 |
| Centre-Forward / Striker | shooting×0.35 + pace×0.25 + passing×0.15 + physical×0.15 + defending×0.10 |

Если у игрока задан `ovr_fixed` — он используется напрямую (игроки из паков).

### Рост рыночной стоимости после матча
За каждый матч игрок получает дельту в % к текущей стоимости:
- Гол: +3.5–5.5%
- Ассист: +1.5–2.5%
- Хет-трик: дополнительно +8–12%
- Два гола: +2.5–4%
- Рейтинг ≥9: +3–5%
- Рейтинг ≥8: +1.5–2.5%
- Рейтинг <5: −1.5–2.5%
- Жёлтая карточка: −0.5–1%
- Красная карточка: −5–8%
- Травма: −4–7%
- Случайный шум: ±2%

### Рост навыков после матча
- Гол → shooting +1–3, pace +0–1
- Ассист → passing +1–2
- Рейтинг ≥8.5 → случайный навык +1–2
- Рейтинг <5 → случайный навык −1
- Красная карточка → physical −2
- Жёлтая карточка → physical −1
- Травма → pace −1–2, physical −1–2
- Защитники/вратарь: сухой матч → defending +1–2; рейтинг ≥7.5 → defending +1; с вероятностью 25% → physical +1

### Травмы
- Хранятся в `player_injuries`: тип, `matches_remaining`
- Травмированный игрок не попадает в автосостав и не учитывается в симуляции лиги
- В матче: при травме — немедленная вынужденная замена (не считается в лимит тактических замен)

### Карточка игрока
Страница игрока содержит: фото, атрибуты, навыки (радар), история рыночной стоимости, статистика матчей (голы/ассисты), трансферная история, достижения, история аренд.

### Загрузка фото игрока
Тренер может загрузить фото любого игрока своей команды через canvas-кроппер (1:1).

## 4. Состав (Lineup)

### Слоты
- Слоты 1–11: стартовый состав
- Слоты 12+: скамейка запасных
- Каждый игрок в составе может иметь `position_override` (зона на поле: GK/DEF/DMF/MID/AMF/FWD)
- Каждый игрок на скамейке может быть отмечен как `priority_sub` = 1 (приоритетный для замены)

### Управление составом
- Тренер перетаскивает игроков по позициям визуально
- Доступна кнопка «Автосостав» — расставляет всех активных здоровых игроков по слотам в порядке позиций
- Дублирующие слоты и игроки блокируются валидацией

### Зональные штрафы в матче (teamStrengthWithZones)
Если ключевые зоны не заполнены:
- Нет вратаря → защита ×0.60
- DEF+DMF = 1 → защита ×0.80; DEF+DMF = 0 → защита ×0.55
- FWD+AMF = 0 → атака ×0.50
- MID+DMF+AMF < 2 → атака и защита ×0.80

**Позиционная матрица штрафов (OVR × коэффициент при игре не на своей зоне):**
```
           GK    DEF   DMF   MID   AMF   FWD
GK       1.00  0.80  0.65  0.55  0.50  0.45
DEF      0.80  1.00  0.88  0.75  0.65  0.55
DMF      0.65  0.88  1.00  0.90  0.80  0.68
MID      0.55  0.75  0.90  1.00  0.90  0.75
AMF      0.50  0.65  0.80  0.90  1.00  0.88
FWD      0.45  0.55  0.68  0.75  0.88  1.00
```
Пример: ЦП (MID) поставлен на ЦАП (AMF) → OVR × 0.90 (соседняя зона).

## 5. Система паков

### Выдача паков
- Каждый тренер получает пак **раз в неделю** (по понедельникам, через cron-задачу)
- Паки могут накапливаться: если тренер не открыл предыдущий, следующий добавляется в очередь
- Тренер видит «Пак N из M» — сколько паков в очереди
- Выдаётся всегда старейший нераскрытый пак

### Покупка пака
- Тренер может купить дополнительный пак за **€1 000 000** из трансферного бюджета
- Кнопка «Купить пак (€1M)» всегда доступна (нет ограничения на количество купленных паков)
- Рядом с кнопкой отображается текущий доступный бюджет

### Содержимое пака
Каждый пак содержит **5 игроков** с фиксированными позициями:
1. Вратарь (Goalkeeper)
2. Защитник (Centre-Back)
3. Опорный/центральный хав (Defensive Mid / Central Mid)
4. Атакующий хав (Attacking Midfield)
5. Вингер (Left / Right Winger)

### OVR и редкость (шансы)
| Редкость | OVR | Шанс |
|---|---|---|
| Common (обычный) | 60–69 | ~65% |
| Uncommon (необычный) | 70–74 | ~22% |
| Rare (редкий) | 75–79 | ~10% |
| Epic (эпический) | 80–84 | ~2.5% |
| Legendary (легендарный) | 85–89 | ~0.4% |
| Icon (икона) | 90–95 | ~0.001% |

### Рыночная стоимость из OVR
| OVR | Стоимость |
|---|---|
| 60 | €200 000 |
| 65 | €600 000 |
| 70 | €1 000 000 |
| 75 | €2 000 000 |
| 80 | €4 000 000 |
| 85 | €7 000 000 |
| 90+ | €10 000 000 |

Промежуточные значения интерполируются линейно, результат округляется до €50 000.

### Механика вскрытия пака
- Карточки игроков показаны рубашкой вниз
- Тренер кликает по каждой карточке → анимация переворота → открывается игрок
- Игроки с OVR ≥ 80 получают специальную анимацию
- Кнопка «Открыть все карты» — открывает все одновременно с задержкой 200 мс
- Состояние открытых карточек сохраняется при переходе на другие вкладки и возврате

### Выбор игрока
- После открытия всех карточек тренер выбирает одного игрока кнопкой «Взять в команду»
- Выбранный игрок: переходит в команду тренера, добавляется в состав (на скамейку, слот 12+)
- Остальные 4 игрока: получают статус `free_agent`, `free_agent_since = NOW()`, попадают в пул свободных агентов и будут выставлены на аукцион в ближайшем окне (13:00)

## 6. Свободные агенты и аукционы

### Кто становится свободным агентом
- Игроки, не выбранные из пака (4 из 5)
- Игроки, которых тренер продал командой (`POST /free-agents/:id/sell`, тренер получает **60% рыночной стоимости**, округлённой до €50 000)
- Игроки, лишившиеся команды при расширенных трансферах

### Ежедневное окно аукционов
- Аукционы открываются каждый день в **13:00** (cron)
- Все свободные агенты без активного аукциона выставляются
- Аукцион завершается в **17:00** того же дня
- Начальная ставка: `max(100 000, round(market_value × 0.5 / 100 000) × 100 000)`
- Минимальный шаг ставки: **€100 000** выше текущей ставки
- UNIQUE ограничение: один активный аукцион на игрока в любой момент

### Правила ставок
- Тренер должен иметь активную команду
- Нельзя ставить больше доступного трансферного бюджета: `transfer_budget − transfer_budget_spent`
- Каждая новая ставка должна быть выше текущей минимум на €100 000

### Завершение аукциона (в 17:05, cron)
**Если были ставки:**
- Игрок переходит к команде-победителю
- Сумма ставки вычитается из `transfer_budget_spent` победителя
- Игрок добавляется в состав (скамейка, свободный слот от 12)
- Запись в таблице `transfers` с типом `free_agent`
- Тренер-победитель получает уведомление «Игрок выкуплен!»

**Если ставок не было:**
- Аукцион получает статус `expired`
- Игрок остаётся в пуле свободных агентов

### Очистка старых свободных агентов
- Каждый день в **17:05** (после закрытия аукциона):
- Игроки, находящиеся в пуле **3+ дней** без активного аукциона, **удаляются**
- На странице свободных агентов отображается обратный отсчёт до удаления

### Просмотр аукциона
- На странице свободных агентов каждый активный аукцион имеет ссылку «Подробнее»
- Модальное окно аукциона содержит:
  - Текущую ставку и команду-лидера
  - Таймер обратного отсчёта (обновляется каждую секунду)
  - Полную историю ставок с временными метками
  - Кнопку быстрой ставки прямо из окна

## 7. Трансферы между командами

### Трансферные предложения (transfer_offers)
Тренер может сделать предложение на игрока другой команды трёх типов:

#### Покупка (buy)
- Сумма ≥ рыночная стоимость игрока
- Сумма ≤ доступный трансферный бюджет покупателя
- При принятии: игрок переходит, бюджет пересчитывается, новость генерируется

#### Аренда через оффер (loan)
- Срок аренды в месяцах (по умолчанию 6)
- Сумма арендной платы (может быть 0)
- При принятии: создаётся запись в `loans`, игрок перемещается

#### Обмен (swap)
- Два игрока меняются командами
- Возможна доплата в любую сторону (`amount`: положительное — платит покупатель, отрицательное — платит продавец)
- Оба игрока не должны иметь активных ожидающих офферов

### Статусы оффера
`pending` → `accepted` / `rejected` / `cancelled`
- Принять/отклонить может только тренер продающей команды (или admin)
- Отозвать может только тренер, сделавший оффер

### Прямая аренда (loan_offers — двусторонняя система)
- **«Взять в аренду» (loan_in)**: тренер заходит в профиль игрока другой команды и отправляет запрос владельцу
- **«Отдать в аренду» (loan_out)**: тренер предлагает своего игрока другой команде
- Срок аренды = конец трансферного окна текущей активной лиги; если лиги нет — +180 дней
- Принять/отклонить может только тренер команды-владельца (lending team)
- При принятии:
  - Создаётся запись `loans`
  - Игрок перемещается в арендующую команду
  - Все остальные ожидающие офферы на этого игрока отменяются (`cancelled`)
  - Оба тренера получают уведомление
  - Генерируется новость
- Вкладка «Аренда» в дашборде тренера показывает входящие и исходящие предложения
- В составе «Мой клуб» арендованные игроки помечены специальным бейджем
- Возврат аренды: `PUT /loans/:id/end` — игрок возвращается в родной клуб

## 8. Товарищеские матчи (Friendly / Match Challenges)

### Вызов на товарищеский матч
- Тренер отправляет вызов другой команде (у которой есть тренер)
- Нельзя вызвать свою команду
- Нельзя отправить два активных вызова одной команде
- Вызов может содержать текстовое сообщение (выводится в деталях матча)
- Принявшая сторона: матч создаётся немедленно (`is_friendly = 1`)
- Отклонить или отозвать вызов — доступно обеим сторонам

### Симуляция товарищеского матча
- Происходит в реальном времени (по расписанию планировщика)
- Механика симуляции идентична лиговым матчам
- Результат не влияет на турнирную таблицу
- Генерируется новость о матче

## 9. Лига (League)

### Создание лиги (admin)
- Название, сезон, список команд (минимум 2)
- Время начала матчей (`match_start_time`, по умолчанию `16:00`)
- Интервал между матчами в туре (`match_interval_minutes`, по умолчанию 15)

### Расписание — двойной круговой турнир
- Генерируется алгоритмом «circle method»
- `N команд` → `2×(N−1)` туров; если нечётное число команд, добавляется «бай» (bye)
- Матчи распределяются равномерно на 30 дней от даты старта
- Порядок матчей в туре: `start_time`, `start_time + interval`, `start_time + 2×interval`, …

### Симуляция тура (admin)
- `POST /leagues/:id/simulate-matchday` — симулирует следующий незыгранный тур
- Для каждой пары берутся активные, нетравмированные игроки
- Матч симулируется (`simulateMatch`), результат применяется (`applyMatchResults`)
- Обновляется турнирная таблица: очки (победа=3, ничья=1, поражение=0), голы, форма
- Генерируются новости по матчам

### Турнирная таблица
Сортировка: очки → разность голов → забитые голы
Форма — последние 5 матчей (W/D/L)
Дополнительно для каждой команды: топ-бомбардиры и топ-ассистенты лиги

### Завершение сезона
- Когда сыгран последний тур → лига сразу переходит в статус `transfer_window` (трансферное окно на 2 недели; это формальность — окно не закрывается само, новый сезон стартует вручную) и **сразу же определяется чемпион** (наибольшее количество очков):
  - Чемпиону присваивается титул в `titles` (плюс индивидуальные титулы всем игрокам состава)
  - Публикуется новость об окончании сезона и чемпионе
  - Данные чемпиона сохраняются в `app_settings[league_champion]` → на главной отображается **баннер чемпиона** (логотип, название, очки)
  - Тренер чемпионской команды получает уведомление «Вы чемпион!»
  - Присуждение идемпотентно — повторные срабатывания не создают дублей (логика в `services/leagueSeason.js`)
- Старт нового сезона: `POST /leagues/:id/next-season` (только из статуса `transfer_window`)
  - Сброс турнирной таблицы, генерация нового расписания
  - Сброс трансферного бюджета всех команд до **€10 000 000**
  - Снятие торговых банов прошлого сезона (инкремент глобального `current_season`)

### Реальный таймер матча
Матчи в лиге запускаются по расписанию (планировщик проверяет каждую минуту):
- За 5 минут до матча: предматчевое уведомление в Telegram
- Ровно в назначенное время: `started_at = NOW()`, `status = 'in_progress'`
- При запросе `GET /matches/:id` во время матча: возвращаются события только до `live_minute = elapsed_seconds / 60`
- В 90-ю минуту: матч автоматически завершается (`status = 'finished'`)

## 10. Кубок / Турнир (Tournament)

### Создание (admin/тренер)
- Название, список команд (минимум 2)
- Команды расставляются по сетке в порядке рыночной стоимости (сидинг)
- Количество раундов: `ceil(log2(N))`
- Если число команд не является степенью 2 — часть команд получает «бай» (проходят без матча)

### Формат
- Single-elimination (на выбывание)
- Каждый раунд симулируется отдельно (`POST /tournaments/:id/simulate-round`)
- Победители переходят в следующий раунд
- Финал → чемпион получает:
  - Титул в `titles`
  - +5% к рыночной стоимости всех игроков-участников
  - **Сезонный OVR-буст +3** для каждого игрока-участника (хранится в `tournament_ovr_boost`, учитывается в симуляции матчей)
  - Буст **сбрасывается в 0** при старте нового сезона лиги
  - Максимальный накопленный буст: +10 OVR (защита от повторных побед в нескольких кубках)

### Ничья в кубковом матче → дополнительное время
- Если после 90 минут счёт равный → матч получает статус `overtime`
- Планировщик автоматически разрешает матчи в `overtime`:
  - 40% вероятность — гол в пользу хозяев (доп. время)
  - 40% вероятность — гол в пользу гостей (доп. время)
  - 20% вероятность — серия пенальти
  - Всё происходит автоматически, без ручного вмешательства

### Название раундов (по числу оставшихся)
| Раунд | Название |
|---|---|
| Финал (2 команды) | Финал |
| 4 команды | Полуфинал |
| 8 команд | Четвертьфинал |
| 16 команд | 1/8 финала |
| 32 команды | 1/16 финала |

## 11. Симуляция матча

### Расчёт силы команды (`teamStrengthFromOVR`)
Основной алгоритм для всех матчей — по `ovr_fixed` (фиксированный OVR из пака):

```
rawOvr = clamp(ovr_fixed + tournament_ovr_boost, 50, 99)
ovr    = (rawOvr − 50) / 49   // нормировка в диапазон [0, 1]
```

Позиции делятся на группы: GK, DEF (CB/LB/RB), MID (DMF/CM/AM), ATK (LW/RW/CF/ST).
Среднее OVR каждой группы (A, M, D, G):

```
attack  = A×0.55 + M×0.30 + D×0.10 + G×0.05
defense = G×0.30 + D×0.40 + M×0.20 + A×0.05
```

Если игроков меньше 11: `attack` и `defense` умножаются на `players.length / 11`.

### Учёт выносливости (stamina)
Каждый игрок имеет `stamina` (0–100). После матча stamina снижается. Перед матчем:
```
factor = 0.65 + (stamina / 80) × 0.35
```
OVR игрока умножается на этот коэффициент при расчёте силы (максимальный штраф −35% при stamina=0).

### Зональные штрафы (`teamStrengthWithZones`)
Если тренер вручную расставил состав по зонам — применяется дополнительная проверка:
- Нет вратаря → защита ×0.60
- DEF+DMF = 1 → защита ×0.80; DEF+DMF = 0 → защита ×0.55
- FWD+AMF = 0 → атака ×0.50
- MID+DMF+AMF < 2 → атака и защита ×0.80

**Позиционная матрица (OVR × коэффициент при игре не на своей зоне):**
```
           GK    DEF   DMF   MID   AMF   FWD
GK       1.00  0.80  0.65  0.55  0.50  0.45
DEF      0.80  1.00  0.88  0.75  0.65  0.55
DMF      0.65  0.88  1.00  0.90  0.80  0.68
MID      0.55  0.75  0.90  1.00  0.90  0.75
AMF      0.50  0.65  0.80  0.90  1.00  0.88
FWD      0.45  0.55  0.68  0.75  0.88  1.00
```

### Формула голов (главный цикл — 90 итераций)
```
RATE        = 0.016
OFFSET      = 0.02
EXPONENT    = 2.0
MAX_PROB    = 0.055

hAtkEff = homeStr.attack  × 0.88^homeRed × 1.03   // домашний бонус атаки +3%
hDefEff = homeStr.defense × 0.85^homeRed × 1.02   // домашний бонус защиты +2%
aAtkEff = awayStr.attack  × 0.88^awayRed
aDefEff = awayStr.defense × 0.85^awayRed

P(гол хозяев/мин) = min(MAX_PROB, RATE × (hAtkEff / (aDefEff + OFFSET))^2)
P(гол гостей/мин) = min(MAX_PROB, RATE × (aAtkEff / (hDefEff + OFFSET))^2)
```

Красная карточка: каждый удалённый игрок снижает атаку ×0.88 и защиту ×0.85.

### Ожидаемое количество голов (при равных OVR)
| Разница OVR | P(победа сильной) | P(ничья) | Ожид. голов/матч |
|---|---|---|---|
| 0 (равные) | ~45% | ~26% | ~2.3 |
| +3 OVR | ~56% | ~24% | — |
| +5 OVR | ~65% | ~22% | — |
| +10 OVR | ~80% | ~14% | — |

### Случайные события (вероятности за минуту)
| Событие | Вероятность/мин |
|---|---|
| Гол (хозяева/гости) | по формуле выше |
| Пенальти (случайный) | 0.8% |
| Жёлтая/красная карточка | 2.8% |
| Прямая красная карточка | 0.12% |
| Травма | 0.4% |
| Блестящий сейв | 2.2% |
| Удар в перекладину/мимо | 1.8% |
| Угловой | 1.5% |

### Стандартные положения (привязаны к силе команд)
**Пенальти:** 76% конверсия.

**Штрафной:**
```
goalP = clamp(0.18 × (atkStr / defStr), 0.08, 0.32)
```
При равных командах ≈18%, у сильно превосходящей атаки — до 32%, у слабой — от 8%.

**Угловой:**
```
goalP = clamp(0.08 × (atkStr / defStr), 0.03, 0.15)
```
При равных командах ≈8%.

### Автогол
- Вероятность при каждой атаке: **1.5%** (было 4%, снижено для реализма)

### Замены (тактические)
- Окно замен: **55–82 минута**
- Лимит: **3 замены** на команду
- Вероятность замены: 5.5% в минуту при < 3 сделанных
- Выходят только игроки с флагом `priority_sub = 1`
- Предпочтение: замена в той же позиционной группе (GK/DEF/MID/ATK)

### Вынужденная замена при травме
- Происходит немедленно в момент травмы
- **Не считается** в лимит тактических замен
- Замещает только игрок с `priority_sub = 1`

### Рейтинг игрока за матч
Базовый рейтинг: 6.0
- Гол: +1.5
- Ассист: +0.8
- Автогол: −1.8
- Жёлтая: −0.4
- Красная: −2.5 (двойная) или −3.0 (прямая)
- Пенальти забит: +1.2; промах: −0.8
- Штрафной забит: +1.3
- Угловой — гол: +0.6 (ассист)
- Блестящий сейв: +0.5
- Травма: −1.5
- Победа (не травмирован): +0.2
- Поражение: −0.2
- Вратарь: победа +1.0, ничья +0.2, поражение −0.8–2.0
- Итоговый диапазон: 3.0–10.0

### Статистика матча (match_stats)
Генерируется из силы команд:
- Владение: пропорционально midfield-силе, ограничено 32–68%
- Удары, удары в створ, угловые, фолы, офсайды

## 13. Уведомления тренера

Тренер получает in-app уведомления (колокольчик 🔔 в навигации, значок непрочитанных):

| Событие | Тип |
|---|---|
| Победа в аукционе за свободного агента | `auction_win` |
| Входящий запрос на аренду | `loan_offer` |
| Аренда принята | `loan_accepted` |
| Аренда отклонена | `loan_rejected` |
| Победа в лиге (чемпионство) | `champion` |

- Уведомления подгружаются каждые 30 секунд
- Максимум 50 последних уведомлений (непрочитанные первые)
- Отметить все прочитанными — одна кнопка
- Клик по уведомлению — отмечает как прочитанное
