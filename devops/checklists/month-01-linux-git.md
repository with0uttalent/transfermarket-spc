# Месяц 1 — чеклист: Linux, Git, Bash, сеть

Практика к Месяцу 1 из `../learning-plan.md`. Задачи привязаны к **реальному
проекту и серверу** `gost-machine` — учишься не в вакууме, а на своём приложении.

Отмечай `[x]` по мере выполнения. У каждого блока есть **«Проверка»** — как убедиться,
что задача реально закрыта (deliverable), и **«Зачем»** — какой навык качаешь.

> Цель месяца: свободно жить в терминале, понимать процессы/права/сеть/логи на своём
> сервере и уверенно работать с git. Это фундамент под Docker и Kubernetes.

## Блок A. Linux: ориентирование и файловая система

- [ ] **A1.** Пройди по своему серверу: `pwd`, `ls -la`, `cd`, `tree` (или `find`).
  Составь карту: где лежит проект, где Docker-данные (`./data`), где конфиг nginx,
  где системные логи.
  - *Зачем:* без свободной навигации всё остальное медленно.
- [ ] **A2.** Разбери права доступа: `ls -l` на `.env`, `data/`, `docker-deploy.sh`.
  Объясни себе каждую колонку (`rwxr-xr-x`, владелец, группа). Поставь `.env` в `600`.
  - *Проверка:* можешь словами объяснить, почему `.env` должен быть `600`, а скрипт `755`.
- [ ] **A3.** Изучи иерархию FHS: что такое `/etc`, `/var`, `/usr`, `/home`, `/tmp`.
  Ты уже видел `/var/log` — теперь пойми систему целиком.
  - *Зачем:* понимать, где что искать в любой Linux-системе.
- [ ] **A4.** Освой поиск: `find`, `grep -r`, `locate`. Найди в проекте все места, где
  читается `process.env`.
  - *Проверка:* одной командой находишь все env-переменные, которые использует приложение.

## Блок B. Процессы, службы, ресурсы

- [ ] **B1.** `ps aux`, `top`/`htop`, `kill`, `kill -9`. Вспомни историю с
  `update-notifier-crash` — теперь пойми её до конца: что такое PID, PPID, зомби,
  сигналы (SIGTERM vs SIGKILL), почему `pkill -f` убивал сам себя.
  - *Проверка:* можешь объяснить, чем `kill 15` отличается от `kill -9` и когда какой.
- [ ] **B2.** systemd: `systemctl status/start/stop`, `systemctl list-units`,
  `journalctl -u <unit>`. Посмотри статус nginx, docker.
  - *Зачем:* systemd управляет всеми службами; ты уже отключал старую `transfermarket.service`.
- [ ] **B3.** Ресурсы: `df -h`, `du -sh *`, `free -h`, `nproc`. Повтори разбор диска,
  который мы делали, но теперь сам, осознанно.
  - *Проверка:* одной цепочкой команд находишь топ-5 самых больших директорий на диске.
- [ ] **B4.** Логи journald: `journalctl --disk-usage`, `--vacuum-size`, `-f` (follow).
  Настрой ротацию, чтобы `/var/log` больше не забивался.
  - *Проверка:* знаешь, как ограничить размер журналов и как смотреть логи в реальном времени.

## Блок C. Bash-скриптинг

- [ ] **C1.** Разбери `scripts/docker-deploy.sh` **построчно**. Каждую конструкцию
  (`set -euo pipefail`, `$(...)`, `if [ ... ]`, `for`, функции, `||`, `&&`) — объясни себе.
  - *Проверка:* можешь на бумаге пересказать, что делает скрипт, шаг за шагом.
- [ ] **C2.** Напиши свой скрипт `scripts/backup-db.sh`: делает бэкап базы из
  контейнера (`docker compose exec`), кладёт в `backups/` с датой в имени, удаляет
  бэкапы старше 7 дней. Используй `set -euo pipefail`, переменные, `find -mtime`.
  - *Проверка:* запускается, создаёт датированный бэкап, чистит старые. (Это ещё и
    реально полезно проекту!)
- [ ] **C3.** Добавь в скрипт обработку ошибок и вывод (`echo`/`printf` с цветом,
  проверка кода возврата). Прогони через [shellcheck](https://www.shellcheck.net/).
  - *Зачем:* хорошие скрипты — основа любой автоматизации в DevOps.

## Блок D. Сеть (базовый уровень)

- [ ] **D1.** `ip a`, `ip route`, `ss -ltnp`. Найди, кто слушает порты на сервере.
  Ты уже делал `ss -ltnp | grep :3000` — теперь пойми вывод полностью.
  - *Проверка:* объясняешь, что такое `127.0.0.1:3000` vs `0.0.0.0:3000` и почему
    контейнер биндится на localhost.
- [ ] **D2.** Разбери путь запроса: браузер → nginx (:80/:443) → `proxy_pass` →
  контейнер (:3000). Посмотри конфиг nginx (`/etc/nginx/`), найди `proxy_pass`.
  - *Проверка:* рисуешь схему прохождения HTTP-запроса до приложения.
- [ ] **D3.** Инструменты диагностики: `curl -v`, `ping`, `dig`/`nslookup`, `telnet`/`nc`.
  Проверь `/api/health` через `curl -v` и разбери заголовки ответа.
  - *Зачем:* 80% отладки сети — это `curl -v` и `ss`.
- [ ] **D4.** Основы: что такое порт, TCP vs UDP, что такое DNS, что такое TLS
  (почему https). Прочитай зины Julia Evans по сетям.
  - *Проверка:* можешь объяснить, что происходит, когда вводишь URL в браузер.

## Блок E. Git (рабочий инструмент №1)

- [ ] **E1.** Основы: `status`, `add`, `commit`, `log`, `diff`. Прочитай главы 1–2 Pro Git.
  - *Проверка:* понимаешь три состояния файла (working dir / staged / committed).
- [ ] **E2.** Ветки и слияние: `branch`, `checkout -b`, `merge`, `rebase` (в теории).
  Пойми, почему мы решили **не** плодить ветки для app/devops, а разделили директориями.
  - *Проверка:* объясняешь разницу merge vs rebase и когда что.
- [ ] **E3.** Удалёнка: `remote`, `fetch`, `pull`, `push`, `reset --hard`. Ты уже
  чинил сбитый upstream через `fetch + reset` — теперь пойми, что именно происходило.
  - *Проверка:* объясняешь, чем `git pull` отличается от `git fetch` + `git merge`.
- [ ] **E4.** История и откат: `git revert`, `git reset` (soft/mixed/hard), `.gitignore`.
  Разбери, почему `data/`, `.env`, `node_modules/` в `.gitignore`.
  - *Проверка:* знаешь, как безопасно откатить закоммиченное изменение (revert vs reset).
- [ ] **E5.** Хорошие коммиты: атомарные, с внятным сообщением. Посмотри историю
  нашего проекта (`git log --oneline`) как пример.
