# DevSecOps — инфраструктурный путь проекта

Здесь живёт **всё, что не про само приложение**: пайплайн, безопасность,
Kubernetes, мониторинг, упаковка инсталлера, а также планы обучения и чеклисты.

Приложение (код transfermarket) остаётся в корне репозитория. Инфраструктура — здесь.
Это один репозиторий (monorepo), но два логических пути, чтобы не терять, где что.

---

## Два пути проекта

| Путь | Где живёт | Тег в диалоге | Что сюда входит |
|------|-----------|---------------|-----------------|
| **Приложение** | корень репо (`routes/`, `services/`, `public/`, `server.js`, …) | `#transfermarket` | фичи, баги, логика приложения, БД |
| **Инфраструктура / DevSecOps** | `devops/` | `#devops` | пайплайн, k8s, безопасность, мониторинг, инсталлер, обучение |

**Правило тегов (введено для нашего диалога):**
- Сообщение с **`#transfermarket`** → доработка самого приложения.
- Сообщение с **`#devops`** → инфраструктурный вопрос: что делать в пайплайне, что
  изучить, какая задача и т.д.

### «Шов» между путями

Несколько файлов в корне обслуживают оба пути (это нормально — они и есть граница):
- `Dockerfile`, `docker-compose.yml`, `.dockerignore` — как приложение упаковано;
- `scripts/docker-deploy.sh` — деплой контейнера на сервере;
- `DOCKER.md` — документация по контейнеризации.

Эти файлы **живут и деплоятся** на проде, поэтому оставлены в корне (перенос сломал бы
`docker-deploy.sh` на сервере). Из `devops/` на них просто ссылаемся.

## Структура devops/

```
devops/
├── README.md              # этот файл — индекс и правила
├── roadmap.md             # дорожная карта пайплайна (12 фаз)
├── learning-plan.md       # план обучения по месяцам (книги + практика)
├── checklists/            # конкретные чеклисты задач по месяцам/фазам
│   └── month-01-linux-git.md
├── k8s/                   # (позже) Helm-чарт, манифесты, ArgoCD Applications
├── ci/                    # (позже) Jenkinsfile, конфиги сканеров
└── installer/             # (позже) air-gapped Docker-бандл для заказчика
```

## С чего начать

1. Прочитать `roadmap.md` — понять общий поток «коммит → прод» и 12 фаз.
2. Открыть `learning-plan.md` — что учить и в каком порядке (9 месяцев).
3. Взять `checklists/month-01-linux-git.md` — первые конкретные задачи руками.

Принцип: **читаешь главу → сразу воспроизводишь на этом проекте/своём стенде →
отмечаешь галочку в чеклисте.** Понимание рождается на стыке чтения и рук.
